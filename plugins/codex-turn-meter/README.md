# 用量 · 每轮更新

本地 Codex MCP App 插件。打开一次并绑定任务后，在本轮开始时更新状态，
本轮结束时更新统计。界面显示上下文参考、输入缓存命中比例、输入和输出 token。
默认统计本轮提问，可展开切换为最近请求或任务累计。

## 使用

安装后在新任务中启用插件，输入「打开当前任务的用量面板」。
已有任务可在面板详情中按对话名称选择。面板不会猜测当前任务。
后续消息由同一张仍然挂载的面板观察。宿主若卸载旧卡片，需要重新打开；
插件不控制原生输入框位置。可手动刷新长任务的中间统计。

## 更新机制

HTML 通过 MCP Apps `postMessage` 桥调用本地 stdio MCP 服务。
面板发出最长 20 秒的 `wait_for_turn` 等待请求；没有变化时返回空结果并续接等待，
不重绘数字。本地服务每 0.5 秒检查选定日志的增量，只有本轮开始、结束或
结束后的迟到统计触发版本变化。没有消息发送的原生回调依赖。
这属于长轮询订阅：界面按交互更新，后台仍有轻量检查与续接请求。
隐藏、暂停和销毁后停止续接，已有等待最多在 20 秒后释放。
自动刷新不调用模型；插件定义和首次工具调用仍可能进入模型上下文。

## 统计

- 输入缓存命中率：`cached_input_tokens / input_tokens`，按 token 计数。
- 上下文参考：最近已上报输入除以上报的窗口上限，生成和压缩期间可能滞后。
- 本轮：任务开始基线与当前累计之差；起点不完整或计数重置时显示未知。
  本轮起点未知（如长日志尾部之外）时，主数字自动回退为最近请求并标注
  「最近请求 · 本轮起点未知」；切换统计范围仍可查看原始口径。
- 累计：日志上报的任务累计，不是 API 账单或订阅额度。
- 推理输出是输出的一部分，不重复相加。
- 首次最多读取日志尾部 8 MB，之后读取完整新增行；重复累计计数去重。
- 新消息入队但尚未形成 `task_started` 时不会提前标为已开始。

## 数据与权限

默认读取 `~/.codex`，可通过 `CODEX_HOME` 指定。
只读打开 `state_*.sqlite` 和 `thread_history_*.sqlite`，定位 `sessions` / `archived_sessions` 中的 JSONL。
返回对话名称、项目标签、更新时间及统计数值，内部通过任务 ID 绑定；不导出对话正文、认证文件或用户配置。
不写 Codex 配置，不监听网络端口，不修改连接方式。

## 兼容性

Python 3.10+，仅标准库。客户端需支持本地插件、MCP App HTML 渲染与
`serverTools` 工具调用，且允许最长 20 秒的调用。服务并发处理等待和手动读取。
首次安装由安装器将 MCP 启动命令绑定到安装时的 Python 路径。
原生宿主的呈现和后台卡片生命周期需在安装后实机确认。

架构参考：https://github.com/jensen1993/codex-usage-plugin 。本实现独立编写，
以按本轮边界更新的紧凑面板为目标。

## 会话列表

列表只显示用户发起的会话：`threads` 中 `thread_source` 为 subagent 或
guardian_review 的机器存根（无名称、通常无回复）不会出现。只保留最近 30 天内
活跃的会话，按活跃度降序最多 50 条；超出时列表末尾提示「已省略 N 个较早会话」，
当前观察的对话即使超出也会保留。活跃度取最后回复完成时间与最近更新时间中
较新者；显示的日期仍只用最后回复时间，没有回复记录显示「暂无回复记录」，
不用修改时间冒充。

项目名称优先使用本地 `projects` / `project_roots` 表，按工作目录与项目根路径的
最长前缀匹配，与客户端侧边栏一致；未关联项目时使用工作目录名，同名目录不再
拆成重复项目组。无名称的用户会话用首条用户消息的前 30 字作为显示名，
仍无内容才显示「未命名对话」。任务 ID 继续作为内部绑定键。
